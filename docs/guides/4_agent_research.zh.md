# Agent 研究入口

Agent 是第四类使用者：以程序方式运行实验、开发方法、修改研究工具，并利用反馈继续迭代。它复用人类使用者、研究人员与维护者的接口。

| 方向 | 改进对象 | 需要的反馈 |
| --- | --- | --- |
| Auto-research | 压缩算法、组合、参数与实验方案 | 质量、效率、训练结果及失败原因 |
| RSI | Agent 自身的研究策略、工具与工作流程 | 在固定研究任务上的效果、成本与回归 |

这里暂将 RSI 按“递归自我改进”理解，具体改进对象与评价协议由后续研究确定。

**现有入口**

能力发现 → 生成配方或方法 → 检查计划 → 运行 → 比较结果 → 修改或恢复。

- 查询与实验：discover_capabilities、run_experiment；计划使用 plan_only。
- 读取反馈：计划读取返回值；正式运行读取 result.json、effective_config.json 和需要的日志。错误提供 type、stage、message；启动早期失败可能尚无结果文件。
- 比较与恢复：复用 compare_runs、restore_config；操作见 [实验指南](1_run_compression_experiment.zh.md)。
- 开发与修复：复用 [方法开发](2_dev_compression_method.zh.md) 与 [维护入口](3_troubleshoot_runtime.zh.md)。

**后续研究需要补齐**

1. 将研究目标、资源预算和停止条件用于选择下一次实验。
2. 将假设、代码/配方版本与运行结果关联，积累可复用的研究记录。
3. 用一致协议比较候选改进；RSI 同时评估 Agent 的研究效果与成本。

这些是未来编排与评价需求，当前接口不等于已经实现自动研究或 RSI 系统。实验执行仍由压缩框架及原生训练/评测后端承担；单次成功不自动升级方法支持状态。
